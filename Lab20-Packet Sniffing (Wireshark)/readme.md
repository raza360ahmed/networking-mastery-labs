# Lab 20 - Packet Sniffing (Wireshark)

## Objective
Capture and analyze live network traffic to understand the
difference between cleartext and encrypted protocols, and to
learn passive traffic analysis technique used in real SOC work.

## Topology Addition
Metasploitable2-Target (192.168.2.13) attached to SW-HQ

## Tools Used
tcpdump   - command-line packet capture
wireshark - GUI packet capture and analysis

## Commands Used
sudo tcpdump -i eth0                Capture all traffic on interface
sudo tcpdump -i eth0 icmp           Filter ICMP only
sudo tcpdump -i eth0 port 80        Filter HTTP traffic only
telnet 192.168.2.13                Generate plaintext login traffic
ssh msfadmin@192.168.2.13          Generate encrypted login traffic

## Wireshark Filters Used
telnet     Isolate Telnet session
ssh        Isolate SSH session
dns        Isolate DNS queries
http       Isolate HTTP traffic

## Tests Performed
Captured full Telnet login session and recovered plaintext
  username and password via Follow TCP Stream
Captured equivalent SSH login session, confirmed only
  encrypted binary data visible - no credentials recoverable
Captured DNS query/response in cleartext
Captured HTTP request in cleartext via Follow TCP Stream

## Key Learning
Sniffing is passive reconnaissance - harder to detect than
  active scanning (Lab 19), since no traffic is generated by
  the observer themselves.
Cleartext protocols (Telnet, HTTP, FTP, SNMPv2c) expose full
  session content, including credentials, to anyone positioned
  to observe the traffic.
Encrypted protocols (SSH, HTTPS) protect content even when
  the exact same traffic path is observed.
Follow TCP Stream is the core Wireshark feature used in real
  incident response to reconstruct attacker sessions.
